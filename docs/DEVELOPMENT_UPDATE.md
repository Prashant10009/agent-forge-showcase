# Release overview: a connected workflow engine

Agent Forge brings orchestration, typed decisions, retrieval, verification, and learning into the same system. It coordinates specialist models while retaining context and experience across the work.

## What the release brings together

| Capability | What it does |
|---|---|
| Jev across automations | Gives Python subsystems a shared way to request typed assessments while retaining their responsibilities and action controls |
| In-house ModernBERT | Uses reviewed platform experience for retrieval and qualified local decisions |
| ModernColBERT retrieval refinement | Reorders dense retrieval candidates before selected context travels onward |
| A unified encoder foundation | Replaces the earlier BGE-M3 foundation with evaluated in-house components and compatible, versioned context representations |
| Ordered council planning | Connects creation, executable steps, and challenge into one plan |
| Evidence-aware execution | Connects the actual executor, tools, files, and completion state to the result |
| Workflow observation | Turns events into questions about completion, recovery, and attribution |
| Architect proposal memory | Retains improvements, corrections, and rejection reasons for future system work |

## Built through sustained work

Structural planning and build cycles can span one to two days of concentrated conversation with models. Research, competing proposals, implementation, review, and correction are part of that process. Selected records from building and using Agent Forge supply material for training and evaluating its components.

The system coordinates the work. The corpus preserves what can be learned from it. Each iteration can contribute better context, more useful decision examples, and clearer evidence of what succeeded or failed.
